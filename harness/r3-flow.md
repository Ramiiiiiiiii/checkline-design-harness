# R3 — 파이프라인

> 인터뷰 라운드 R3 확정본 (기본값 승인, 2026-10-10). 근거: `r2-purpose.md`, `docs/story-work.md` ①~⑦

## 단계

| Phase | 이름 | 입력 | 하는 일 | 출력 | story-work |
| --- | --- | --- | --- | --- | --- |
| P1 | 진단 | prd.md, story-service.md, AS-IS 설명 | AS-IS(종이 점검표·엑셀·메신저)를 UI/UX 관점(정보 구조·작업 흐름·사용 환경·시각 위계)으로 진단, UIBowl에서 대시보드 레퍼런스 수집 | `p1-diagnosis/diagnosis.md`, `p1-diagnosis/references.md` | ①② |
| P2 | 설계 | P1 출력, design.md | 대시보드 정보 구조와 화면 스펙. 유저스토리·서비스 규칙 연결, 추가 요소 `[추가 제안]` 표기 | `p2-spec/screen-spec.md` | ③ 일부 |
| P3 | 시안 | P2 출력 | 방향이 다른 시안 **3개**를 **웹·라이트 1장씩** Figma에 제작, 시안별 "해결한 문제" 작성 | Figma P3 페이지 3프레임, `p3-concept/concepts.md` | ③ |
| P3-선택 | 사람 선택 | concepts.md | 내가(또는 클라이언트와) 1개 선택 | `p3-concept/approval.md` (**사람만 작성**) | ④ |
| P4 | 확장 | 선택안 | 웹(1920)·태블릿(1280×800)·모바일(360×740) × 라이트·다크 = **6프레임**. DS에 없는 표 조합만 여기서 제작 `[DS 없음 · 조합]` | Figma P4 페이지 6프레임, `p4-expand/screens.md` | ⑤⑥ |
| P5 | QA | P4 출력, rules.yaml | DS 규칙·서비스 규칙·추가 요소 표기 검사 | `p5-qa/qa-report.md` (**스크립트만 작성**) → 최종 승인 | ⑦ |

## 되돌아가는 지점

| 실패 / 반려 | 돌아가는 곳 |
| --- | --- |
| P1·P2·P4 게이트 실패 | 같은 Phase에서 다시 (최대 3회) |
| P3 시안 3개 모두 반려 (방향 문제) | P3 다시 |
| P3 반려 사유가 "문제를 잘못 짚음" | **P2** 설계로 |
| P5 QA 실패 | **P4** 수정 |
| 같은 게이트 3회 연속 실패 | 멈추고 나에게 보고 (blocked) |

## 결정 사항

- story-work ⑤의 토큰·컴포넌트 제작은 별도 단계로 두지 않는다. 원티드 DS를 그대로 쓰고, DS에 없는 표 조합만 P4에서 만든다.
- 시안 단계에서는 다크·태블릿·모바일을 만들지 않는다 (시안 3 × 6 = 18장 방지).
