# P2 설계 — 관리자 설비 현황 대시보드

> 기준: docs/prd.md §3-2·§3-3·§6-4·§6-5·§6-6·§8, docs/story-service.md, runs/admin-dashboard/p1-diagnosis/*
> 플랫폼: 웹 1920 (P4에서 태블릿·모바일로 확장)

## 목적
종이·엑셀·메신저에 흩어진 설비 상태를 한 화면에 모아, 관리자가 **위험(가동 정지·이상)부터** 보고 바로 조치(수리 배정·미점검 알림)하게 한다. 해결 대상: D1(전체 현황 없음), D2(이상 보고 지연), D3(정지 설비 구분 안 됨), D4(미점검 파악 불가), D5(수리 추적 불가), D6(PC 정보 밀도).

## 연결 유저스토리
- US-3: 관리자가 라인별 오늘 점검 현황·미점검 설비·이상 보고를 한 화면에서 보고 미점검자에게 알림을 보낸다 (PRD §3-2, §6-4)
- US-4: 관리자가 이상 보고의 위험 등급을 확정하고 수리 담당자를 배정한다 (PRD §3-3, §6-5)
- US-5: 수리 담당자가 남긴 수리 완료를 관리자가 확인한다 — 재가동 확인 (PRD §6-6)

## 상태
| 상태 | 표현 | 변수 |
| --- | --- | --- |
| 정상 | 텍스트 "정상" | Status/Positive |
| 이상 | 텍스트 "이상" | Status/Cautionary |
| 가동 정지 | 아이콘(경고) + 텍스트 "가동 정지", 위험 알림 영역 최상단 고정 | Status/Negative |
| 미점검 | 텍스트 "미점검" | Interaction/Inactive |
| 수리 중 | 텍스트 "수리 중" | Accent/Foreground/Violet |

- 가동 정지는 수리 완료 + 관리자 재가동 확인 전까지 어떤 영역에서도 "정상"으로 표시하지 않는다 (★1, PRD §8-1).
- 빈 상태: 위험 알림이 0건이면 "지금 확인할 위험이 없어요" 한 줄 (Label/Alternative).

## 추가 제안
- [추가 제안] 이상 보고 경과 시간 표시 — PRD 기능 목록(§5-1)에는 없음.
  - 표시 조건 (사용자 결정, 2026-10-10): **긴급(위험 등급 "즉시 정지")은 항상** 표시, **그 외는 보고 후 24시간이 넘은 것만** 표시.
  - 근거: 긴급 건은 PRD §9 "30분 이내 배정" 목표를 바로 확인해야 함. 일반 건까지 분 단위로 보이면 담당자에게 불필요한 압박이 되므로, 하루 넘게 방치된 것만 드러낸다.
